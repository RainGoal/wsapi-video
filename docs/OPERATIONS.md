# 运行与发布说明

## 服务与配置

一个 API 进程内启动四个有数据库租约的媒体 Worker、一个支付核查循环及邮件 outbox。多实例依赖 PostgreSQL 行锁、唯一流水与租约 fencing，不依赖浏览器保持开启。关闭时停止接收请求并取消后台上下文；未知提交留待核查。

应用启动先验证部署配置并执行事务迁移，再启动服务。`APP_SECRET`、数据库地址、监听地址、`PUBLIC_URL` 等部署参数由服务环境提供；Sub2API、易支付、SMTP、S3 的日常配置主要通过 **运营后台 → 系统设置** 管理。运行配置和历史凭证版本使用由 `APP_SECRET` 派生的密钥进行 AES-GCM 加密，密文进入数据库，秘密不进入前端包和审计详情。`.env`、本地数据库、验收凭证和媒体均被 Git 忽略。生产由 HTTPS 反向代理对外，应用端口仅绑定可信网络；不要暴露 PostgreSQL。

将 `PUBLIC_URL` 设为浏览器实际使用的唯一 HTTPS origin。后端对写请求校验 Origin，保护接口同时校验 Cookie 会话和 CSRF。易支付通知由签名和主动查单保护。代理不得将用户任意输入的 Host 用作平台公共地址，也不要缓存认证 API。

S3/R2 bucket 保持私有，按最小权限授权读写指定 bucket。服务端临时签名地址用于上游读取参考素材，原始 Key 不给浏览器。生产私有对象预览重定向若使用不同 origin，需将该实际 origin 加入服务器 CSP 的媒体策略；当前策略允许 HTTPS 图片/媒体，浏览器 fetch 仍限定同源。

## 初装与后台配置

首次正式部署使用独立数据库、`APP_ENV=production`、`DEMO_MODE=false`、HTTPS `PUBLIC_URL`、随机且至少 32 字符的固定 `APP_SECRET`、`STORAGE_DRIVER=s3` 和 `APP_SETUP_MODE=true`，并提供 bootstrap 管理员。初装模式要求数据库中已有正常且邮箱已验证的管理员，或本次启动成功创建该管理员。创建后移除 bootstrap 密码。

SMTP/S3 尚未填写时可进入管理员后台，但 `/readyz` 返回 503。先完成邮件和私有存储，再接入媒体与支付，最后开放对应商品和充值档位。公开注册同时受注册开关、SMTP 和私有存储就绪条件控制。初装模式不会允许生产使用本地存储或演示模型，也不会跳过配置解密和字段验证。

后台保存配置后实时生效，不需要重启；在多个管理员同时编辑时使用 revision 防止覆盖。发生 409 时先保留当前输入，重新加载并核对其他管理员的变更后再提交。读取只返回凭证是否存在；密码框空白表示保留，非空表示替换，清除须显式勾选。所有写操作需 CSRF 与管理员会话，并记录变更字段名称和原因。

在系统设置的站点分区填写素材保留期限、容量说明、清理规则、提交未知/长期冻结处理期限及退款/迟到成品政策。各项默认空、最多 2000 个 Unicode 码点，保存后通过公开政策入口展示；正式开放前需核对这些声明与实际操作一致。政策文本本身不会创建存储配额、定时删除或自动退款，人工处置仍遵循任务与账本约束。政策为空时用户会看到待运营公布，不能视为已经给出服务承诺。

首次后台保存前，环境变量可作为初始配置来源；保存后数据库内配置成为运行依据。若 SMTP/S3 由数据库管理，后续部署继续保留 `APP_SETUP_MODE=true`，使启动阶段不要求环境中再复制这些凭证。该变量不表示服务已就绪；仍须检查 `/readyz` 和真实业务验收。数据库不可读取或密文解密失败时拒绝相关操作，不回退到旧环境配置接单。

存储 driver、Endpoint、区域和 Bucket 在首次对象操作前持久锁定；失败的首次上传也可能保守地锁定，删除全部素材不会解锁。已有冻结任务同样阻止切换位置。后台只允许同一位置的凭证替换；S3 已有素材时不能清空访问凭证。更换位置必须停机、离线复制对象、核对数据库引用与文件完整性，并通过运维迁移完成，不能删锁记录绕过保护。

## 凭证版本与连接检测

后台修改媒体或支付配置时会建立新的加密凭证版本。已接受任务保留原媒体 origin、白名单与凭证引用，支付订单保留原商户、支付 origin、通知配置及凭证引用；当前配置切换不把旧业务改投新账户。旧版本必须随数据库保留，不能因当前页面显示新 Key 已配置就删历史版本。清除当前 Key 只影响新业务的可用性，不是清理历史版本的工具。

旧部署使用的 `MEDIA_KEYS_JSON`、`EASYPAY_KEYS_JSON` 是初始环境配置来源。后续轮换从后台完成，数据库保留原引用版本；不要用改 `.env`、改任务行或删密文来代替轮换。外部供应商提前吊销旧 Key 仍会使在途任务无法核查，应先完成或人工决议旧业务。

后台检测只针对已保存配置，结果附带时间并记录审计：

| 分区     | 检测内容                                   | 仍需单独验收                                   |
| -------- | ------------------------------------------ | ---------------------------------------------- |
| 生成网关 | 用已填写凭证只读请求 `/v1/models`          | 逐商品生成、参考编辑、轮询、原凭证下载与归档   |
| 易支付   | HTTPS `submit.php` 接口可达                | 商户 Key、签名、通知、查单、精确金额和唯一到账 |
| SMTP     | 连接、TLS、可选认证后退出；不发送邮件      | 验证/重置邮件发送、收件、垃圾箱与链接可达      |
| 私有存储 | 本地位置访问或 S3 `HeadBucket`；不写删对象 | 上传、对象读取、私有授权、签名地址与删除权限   |

SMTP 支持 465 隐式 TLS，其他端口要求 STARTTLS。连接检测成功和“已配置”只反映相应范围，不构成正式发布证明。

## 模型商品开放流程

1. 使用网关实测确认 model ID、类型、尺寸、比例、时长、参考数量/类型、音频和取消能力。
2. 创建商品并配置零售积分、能力，保持下架。所有真实商品默认不开放。
3. 用独立测试账号和明确测试预算验证文生、参考编辑、状态查询、原凭证内容下载和平台归档。确认一任务一作品。
4. 在模型商品表单中校对能力和零售价，勾选已验证并上架。图片与视频 Key 分开；原凭证引用在在途任务完成前不能移除。

Sub2API 当前公开图片异步任务有 TTL、网关重启执行恢复边界，且没有已验证的客户端创建幂等恢复协议。平台不会以盲目重复创建掩盖这些限制。网关公开接口的新改造在另一个项目进行，本仓库不修改该工作区。

### 视频零售定价

视频商品选择“按次”或“按秒”，填写默认单位积分，并可为已配置的各分辨率填写覆盖积分。一个商品的所有分辨率共用计费单位；分辨率价格优先，未填写的分辨率使用默认价格。切换计费单位保留输入数值，不自动换算。图片商品继续固定单次积分。

- 按次：总积分 = 该分辨率单位积分。
- 按秒：总积分 = 该分辨率单位积分 × 用户选择的请求时长（秒）。不按实际成片或参考视频时长追加扣费。
- 单位积分为正整数；单次报价总额不超过 1,000,000,000 积分。按秒商品必须配置可选时长，所有可选规格均须在金额上限内。

例如默认 5 积分/秒、1080p 覆盖 8 积分/秒：720p、10 秒报价 50 积分；1080p、10 秒报价 80 积分。按次商品同样支持分辨率覆盖，但选择时长不改变费用。

报价先规范化时长和分辨率，再冻结商品版本、定价规则、输入及总额。用户确认后冻结该总额；归档成功消费，失败或确认取消释放，退款沿用原任务总额。后台调整单价、计费单位或分辨率覆盖价不修改已生成报价与已接受任务，也不撤销已经确认的模型能力验证。未配置新定价规则的旧视频商品继续按原固定单次积分收费。

平台定价单位是零售积分，与 Sub2API 的美元采购价独立管理。Sub2API 新版还支持实际输出秒数、输出加参考秒数等计量策略；这些依赖可信计量与差额结算，当前平台采用请求时长固定报价，不自动导入上游美元价格或跟随其采购结算方式。

## 异常任务决议

- 媒体交付前检查实际载荷；MP4/WebM/WebP/压缩音频需可用 ffprobe，解码像素不超过 64,000,000、单线程、最长 15 秒。解码失败或超时不作为成品结算。恢复旧归档在字节校验后重做媒体检查，并使用临时磁盘；发布前按真实规格验证 CPU、并发和暂存容量。GIF 只检查首帧，WAV 目前为结构检查，不能以探测成功承诺所有浏览器编码兼容。
- `archive_kind_mismatch`：归档实际媒体类型与购买的图片/视频任务不符。交付转 error、采购 disputed，积分继续冻结；新归档和既有归档恢复共用检查。先保留对象及证据并核查上游；原对象未纠正时“重试归档”仍会拒绝结算，不能直接改素材记录或任务成功状态。
- `submission_unknown`：可能已经受理，不自动再次创建。运营先核查网关原请求；查到任务后绑定原 upstream ID 继续轮询，确定未受理后才释放冻结。证据与原因必填并留审计。
- `generating` 超期：维持冻结并转待核查。暂时查不到、凭证失效、任务过 TTL 都不等同于明确失败。
- `completed / archive_retry`：上游已完成，平台尚未成功归档。仅重试下载/保存；签名失效可重新查询原任务刷新地址，不重新生成。
- 若作品已写入私有存储和素材表，但进程在任务关联/结算前中断，Worker 按原任务 ID 校验已归档文件的大小与 SHA-256 后恢复结算，不再次请求上游。数据库提交响应丢失时保留对象，避免误删已提交作品；未确认的孤儿对象只在离线对比数据库、完成备份并确认无引用后清理，不能按上传失败日志直接删除。
- `ready / consumed`：作品已在平台私有存储保存并结算。运营退款是独立唯一流水，不删除作品、不影响网关采购事实。
- `canceled`：仅明确未发送或上游确认取消后释放；不支持取消的商品返回明确说明。

用户画布与分镜的删除、复制、撤销和项目归档都不执行以上资金操作。采购核查状态独立于零售结算；运营释放/退款不意味着网关一定退回采购费用。

## 易支付验收与对账

配置确切 HTTPS origin、PID、Key 和公网 notify/return URL，先使用测试商户和小额档位。后台打开档位前完成以下验证：正常支付、重复通知、漏通知主动查单、金额/商户/签名错误、迟到支付和同一渠道交易号重复使用。

支付返回页面只查询本平台订单。只有通知验签且主动查单一致，或可信主动查单明确已支付，才能按订单锁定的金额和积分入账。订单 `out_trade_no`、服务凭证、PID、provider origin 和价格快照固定保存；订单入账与唯一流水在同一事务中完成。

后台每 15 秒批量领取需要核查的订单。网络失败延后重试，不把请求失败当作支付成功。逾期订单也保留后续核查窗口以接收迟到支付。支付密钥通过后台轮换，数据库中的旧凭证版本保留到历史未决订单全部处理，不能提前删除。

每日对照渠道订单、平台 payment_orders 和 wallet_ledger 的 recharge 流水。未完成对账时不要通过 SQL 修改余额或伪造已支付状态；使用带原因、去重键和审计的后台调账。

## 备份、恢复与升级

- PostgreSQL 定时 `pg_dump` 或云数据库快照；同时备份对象存储并启用适用的版本/保留策略。只备份数据库不足以恢复媒体。
- 数据库备份须包含 `runtime_settings`、`runtime_credential_versions` 和存储位置锁；将对应 `APP_SECRET` 在有独立访问控制的密钥系统中配对保管。仅有数据库密文而没有原主密钥不能恢复服务，更换主密钥需离线重加密。
- 同时保管部署环境参数与对象存储位置；恢复到隔离环境时先阻断真实支付、媒体和邮件出口，避免在途任务继续产生外部操作。
- `local` 存储的位置锁包含应用看到的绝对 `STORAGE_DIR`，同位置恢复须保持该绝对目录。隔离容器或沙箱可将对象副本挂载到与原应用相同的内部绝对路径，并确保挂载的是隔离副本；只改 `STORAGE_DIR` 指向另一个目录会被位置锁拒绝，不能删锁或改锁哈希绕过。跨位置迁移须另行完成离线迁移与核验，当前没有自动重定位功能。
- 按“数据库 + 对象 + 配置”恢复后检查迁移校验和、用户登录、画布节点与连线、独立图片/视频的原文件下载、资产字节数、钱包可用/冻结和流水总额。历史 shots 数据同样保留，但不要求恢复镜头选定流程。核查在途任务后再恢复 Worker 外部访问。
- 迁移仅新增且事务执行；上线前备份，发布失败先退回兼容该 schema 的旧应用。不得修改已应用 SQL，不提供自动破坏性 down migration。
- `.runtime/postgres` 是开发工具数据，不作为生产备份方案。Docker 数据卷也需要独立备份，不要通过删除卷修复升级问题。

本机已完成一次 [原生数据库与媒体副本隔离恢复](QA_LOCAL_RECOVERY_2026-10-17.md)，证明该样本的逐表数据、文件字节、加密配置及迁移记录保留。它没有覆盖生产 S3、恢复库完整应用运行或保留卷回滚，正式发布仍须在目标基础设施演练。

## 发布检查与监控

`/healthz` 提供进程检查；`/readyz` 检查数据库、运行配置可读取性与生产 SMTP/私有存储配置。配置字段已齐不代表外部系统实际连通；媒体与支付仍需各自联调。后台概览展示素材逻辑容量、冻结与异常任务计数；它不等同于 S3 实际账单或网关采购余额。对 API 错误率、Worker claim 错误、冻结超期、未知提交、归档重试、邮件积压、数据库/存储容量设置外部告警。

后台待处理信号提供同一数据库快照下的准确数量、最早记录时间与有限对象样本，并能定位任务/订单。外部机器使用专用只读角色运行 monitor CLI，不需要管理员会话或应用写权限；接口、最小列授权和消费边界见 [监控接入](MONITORING.md)。信号读取不等于通知送达，正式开放前仍须配置接收人和渠道并演练。

正式开放前必须完成真实网关、商户、SMTP、S3、HTTPS反代联调，以及备份恢复和回滚演练。这些外部验收不能由演示图片或单元测试替代。Docker 构建与 CI 配置已提供，本机未安装 Docker 时不能声称已验证容器运行。
