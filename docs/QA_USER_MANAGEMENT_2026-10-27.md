# 后台用户管理第一期验收

日期：2026-10-27。第一期代码与本地验证完成；本验收完成时尚未提交、推送或部署至现有服务及生产环境。

## 已实现范围

- 独立用户列表：搜索、状态、邮箱验证、角色、注册日期、排序及分页；筛选与详情位置随 URL 保存，支持刷新和浏览器返回。
- 后台新增普通用户：填写邮箱、昵称、初始密码、内部备注及原因；用户、零余额钱包、验证邮件任务和审计同事务创建，重复邮箱返回 409。
- 用户资料维护：昵称、内部备注和普通用户邮箱；修改邮箱后重新验证，撤销已有会话、验证与重置令牌，保留原用户编号及业务归属。
- 用户详情：概览、积分流水、任务与订单、安全及操作记录；关联列表按用户编号精确筛选，积分调账入口预选当前用户。
- 账号管理：沿用有原因及审计的启停、撤销会话；新增补发验证邮件、发送重置密码邮件及准确的邮件状态展示。
- 首次改密：后台创建的用户验证邮箱后首次登录须更换初始密码；前端先显示改密页，后端同时限制业务接口；改密后旧会话失效。
- 审计：管理员、目标用户、原因与资料前后值；不返回密码、邮件令牌、邮件正文或原始 SMTP 错误。

本期不含角色修改、批量操作、导出或用户运营统计。管理员邮箱在此处暂不支持修改。余额修改继续使用独立调账流程。

隔离 API 位于本机 `127.0.0.1:8096`，使用专属 `phase1_ui` 数据库和合成账号；实际新增用户、修改资料及补发验证邮件，未触及现有业务库。

- 用户管理脚本 11 项断言通过：资料持久化、补发审计、SMTP 未配置提示、可读审计、任务精确跳转、浏览器返回恢复、调账目标预选、筛选刷新保留、移动端宽度、英文界面及无页面异常。
- 首次改密脚本 7 项断言通过：登录门槛、工作区未挂载、业务 API 被后端拒绝、禁止复用初始密码、改密结束旧会话、新密码登录及无页面异常。
- 移动端补充 2 项断言通过：编辑按钮可点击、详情抽屉命中层级高于导航；最终截图已人工检查。修复仅限用户页父容器动画形成的叠放上下文。

三份脚本共 20 项断言；实际新增用户另行完成，不额外计入。调账只核对预选，未提交积分调整。首次访问的 `/me` 401、favicon 404，以及故意核验门槛的业务 403 均不计为未处理页面异常。

## 升级与验收边界

部署新版程序时自动执行 `backend/migrations/009_user_management.sql`，新增用户字段、审计前后值及邮件生命周期字段；旧用户默认无需首次改密，已应用的旧迁移未修改。操作说明见 [运行手册](OPERATIONS.md)。

SMTP 未配置仍可后台开户，但需要配置后补发验证邮件。真实 SMTP 投递、收件箱与链接可达仍待目标环境验收；本机 SMTP 成功/失败夹具及“邮件服务器已接收”不能替代真实收件结果。本轮没有真实模型调用、支付、生产数据库变更或生产部署。
