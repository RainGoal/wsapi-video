## 本轮修复

- 生成提交在 POST 前写入并读回原报价和 request_key；损坏、不可写、已有不同提交或缺少 Web Locks 时阻止发送。同账号/项目的持久化和清理使用同名 Web Lock，网络请求位于锁外。通用失败及未知请求的重试保留原键；回执须为有效且属于当前项目的 Task。确认后清理失败时，本页只重试清理，不再 POST；旧回执不能清除另一标签的新记录。异步提交期间禁止关闭和编辑，旧项目晚回不更新新项目。
- 后端在报价行锁内先恢复已受理同键任务，再检查过期；明确未受理的过期报价返回 `409 quote_expired`。其他冲突保留 `conflict`，不能作为清理未知请求的依据。
- 分镜新增可选 `excluded_candidate_ids`。手动移除的候选不被历史交付立即回填；新交付仍可追加，保留候选顺序和既有选定。显式重新加入会移除排除项；移除当前选定会清空该选定。后端保存、读取和复制保留排除项，拒绝矛盾状态；排除项不构成素材引用。旧文档兼容，JSONB 不需要新迁移。
- 同项目视图共用画布撤销/重做历史。素材抽屉、素材视图及生成受理后的布局追加均建立独立历史步骤；保存和轮询不清历史，成功云端载入或明确恢复草稿才重置。保持 50 步、深克隆；刷新或离开项目不承诺保留历史。撤销布局不会取消任务或改变积分。
- 商品和充值档位的新建 UPSERT 增加事务读取版本条件。两管理员同时创建同一 ID 时，一方成功、一方 409；保留胜者完整配置、版本和唯一审计，不静默覆盖。
