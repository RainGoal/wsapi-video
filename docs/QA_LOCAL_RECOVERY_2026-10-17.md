# 本机数据库与媒体恢复演练

执行时间：2026-10-17 17:29（Asia/Shanghai）。范围是本机独立平台 Demo 数据与本地媒体，不是生产 S3 或容器回滚验收。

## 方法与隔离

- 使用 PostgreSQL 官方分发的 16.4 `pg_dump` / `pg_restore`，没有以应用自制 JSON 格式替代数据库备份。
- 源库保持在线，以只读 repeatable-read 事务导出 snapshot；备份与逐表基准清单使用同一 snapshot，避免把并发变化误判为恢复差异。
- 只读备份源库 `public` schema。恢复目标是新建的 `frame_restore_20261017_172945`；清理恢复对象的参数只对这个隔离新库执行。未清空或恢复覆盖源库、联调库或原数据库目录。
- 复制数据库引用的本地对象到单独目录，分别核对源文件和副本的长度及 SHA-256。恢复验证期间没有启动 Worker、Mailer，也没有调用外部模型、支付或邮件服务。
- 对应部署配置与主密钥仅保存在 Git 忽略的本机证据目录，不写入本文件或聊天。生产应将密钥与数据备份分开保管并实施访问控制。
